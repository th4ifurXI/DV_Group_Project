# Mini Market Seri Iskandar (simulated) - Sales & Inventory Dashboard

Data Visualization (TEB3133) group project - a Streamlit dashboard that helps the manager of a small
Malaysian mini-market decide what to stock, who to retain and when to reorder.

> **Data note:** the dataset in `data/` is **simulated**. It was generated by
> `data_generation/generate_dataset.py` to resemble a neighbourhood mini-market in Seri Iskandar, Perak
> (Malaysian products and RM prices, local payment methods, UTP students / residents / staff as members,
> the UTP semester calendar, Ramadan, Hari Raya and Chinese New Year). It does not come from a real store.
> The column structure follows common public retail datasets (Kaggle *Supermarket Sales*, UCI *Online Retail II*),
> so a real shop can upload its own POS export in the same format from the sidebar.

## Run it

```bash
pip install -r requirements.txt
streamlit run app.py
```

To rebuild the dataset (same seed = same data): `python data_generation/generate_dataset.py`

## Pages

| Page | Manager's question | Main visuals |
|---|---|---|
| Executive Overview | How is the business doing? | KPI tiles with % change, revenue trend with festive bands, revenue by category, payment-method mix |
| Product Performance | What should we stock more / less of? | Top & bottom 10, Pareto curve, margin by category, slow-mover table |
| Customer Insights | Who are our best customers, who are we losing? | Rule-based RFM segments, downloadable customer lists, spend heatmap by shopper type, cohort retention |
| Seasonality & Timing | When to prepare stock and staff? | Weekday x hour heatmap, daily trend with festive and semester-break bands, Ramadan category change |
| Returns & Losses | Where are we losing money? | Refunds per month, refunds by reason, most-returned products |
| Inventory Alerts | What do we reorder now? | Reorder-point table with status, what-if sliders, purchase list download, stock value by status |
| About the Data | Where does the data come from? | Data note, cleaning log, data dictionary |

No machine learning is used - all analysis is descriptive and rule-based.

## Repository layout

```

data_generation/generate_dataset.py   the simulation script
```

## Dataset summary

| File | Rows | What it holds |
|---|---|---|
| transactions.csv | ~338k line items | POS lines, 1 Jan 2025 - 31 Oct 2026, incl. returns and deliberate data-quality issues |
| products.csv | 99 | product, category, brand, selling and cost price, supplier, lead time |
| customers.csv | 2,600 | loyalty members: shopper type, gender, age group, area, join date |
| inventory.csv | 99 | stock on hand at 31 Oct 2026 |
| calendar_events.csv | 17 | festive seasons and UTP semester breaks used in the simulation |

Deliberate data-quality issues for the cleaning step: duplicate rows (POS double scans), cashier test scans at RM0,
blank product names, walk-in customers with no ID, and returns with negative quantities.
